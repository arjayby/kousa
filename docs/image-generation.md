# Image generation

Image nodes generate through the existing Vercel AI Gateway key and save the result in private project storage. No additional environment variables, provider keys, or paid plan activation are needed for local development. Run `pnpm dev` from the repository root so Alchemy applies migrations through `0009_durable_generation`, starts the jobs Worker, and supplies its bindings.

## Model and credits

The first model is `bfl/flux-2-klein-4b`, FLUX.2 [klein] 4B. It was verified as eligible in [Vercel's free-tier image catalog](https://vercel.com/ai-gateway/models?freeTier=true&type=image) on September 17, 2026. Eligibility and the remaining Gateway allowance are controlled by Vercel; no paid-model fallback is configured. See the [model page](https://vercel.com/ai-gateway/models/flux-2-klein-4b).

Each successful saved image costs **3 Kousa credits from the person running it**. This is provisional sandbox pricing, separate from Vercel's USD allowance. Owners and editors can run; viewers can see and download results. Both image and text generation share the limit of one active run per payer and per node.

| Aspect ratio | Requested size |
| --- | --- |
| 1:1 | 1024 × 1024 |
| 16:9 | 1024 × 576 |
| 9:16 | 576 × 1024 |
| 4:3 | 1024 × 768 |

The server allows only the catalog model and these sizes, with one image per request. Prompt input is limited to 12,000 UTF-8 bytes. The Gateway call has a 90-second timeout and no SDK retries.

## Canvas behavior

1. Select an Image node. Write a prompt or connect a Text output to its Prompt input.
2. Choose the aspect ratio and wait for the canvas to finish saving.
3. Click **Generate image**. The latest successful result appears on the node and in its settings.
4. Use **Download image** to save a copy. **Show on node** can switch between the latest generation, another saved project image, or no image.

Connected text uses its last successful generated output, falling back to its written text. Upstream nodes do not run automatically. Uploaded images are retained in the project library but are not sent to the model as references. Reference connections are explicitly rejected for this milestone. Failed retries retain the last successful result. Collaborators receive result updates through the existing three-second polling; image metadata refreshes every ten seconds.

## Persistence and failure behavior

The saved graph determines the model, size, prompt and connected sources. A client hash detects unsaved or conflicting prompt changes. The browser cannot supply a generation price, output, payer, or arbitrary provider URL.

`generation_run` records the kind and generated asset ID alongside the existing reservation. Queued and running reservations expire after thirty minutes. Available credit calculations release expired reservations immediately; the next list or claim marks abandoned rows failed. Replaying a request ID never repeats a provider call.

The workflow first saves a private response receipt in R2, then the media service validates and stages the generated bytes. Storage and finalization steps retry without repeating the AI call. Its existing file and project quotas apply. The `kousa_finish_image_generation` Postgres function rechecks editor access and atomically marks the asset ready and the run successful. A failed or expired run cannot publish a new staged file or spend credits. A database error after finalization is treated as uncertain, never as a reason to refund an already committed run. The browser's **Check run** action uses the same request ID.

Use migrations, not `db:push` alone: the Drizzle schema does not represent these Postgres functions. Existing text runs retain their output and billing state.

Local files live in the persistent R2 emulator under `apps/web/.wrangler/state`; Neon stores metadata. See [project media](project-media.md) for production activation and local storage limitations. Interrupted staging can leave pending assets that count toward the quota; automatic cleanup is not implemented yet.

Generation runs in [durable background jobs](background-generation.md). You can reload or leave the canvas after queuing. If the Worker terminates during the provider call before a receipt is saved, the application may still incur provider usage without a deliverable result. Recovery releases the user's reservation instead of automatically repeating a potentially billable call.
