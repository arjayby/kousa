# Resend email for Kousa

Kousa uses Resend for project invitations and Better Auth email verification. The sender is `invites@mail.kousa.app`. Namecheap remains the registrar for `kousa.app`, and Cloudflare hosts its DNS and the application.

Resend's [free transactional plan](https://resend.com/pricing) currently includes 3,000 emails per month, with a limit of 100 per day. Invitations and verification emails share that allowance. This integration calls Resend over HTTPS and does not require Cloudflare's paid email service.

## Account and domain setup

1. Sign up at [Resend](https://resend.com/signup) and keep the free plan.
2. Open **Domains → Add Domain** and enter **mail.kousa.app**. Choose a sending region closest to most recipients; keep the default Return-Path setting.
3. Copy the exact sending DNS records generated by Resend into **Cloudflare → kousa.app → DNS → Records**. These include DKIM and SPF records; use the record types, names, values, and MX priorities shown by Resend. Keep any CNAME records **DNS only**. Do not replace existing root-domain mail records or enable receiving for this integration.
4. Return to Resend and complete domain verification. Keep click and open tracking disabled for these transactional emails so invitation and verification links are not rewritten.
5. Open **API Keys → Create API Key**. Name it `kousa-dev`, choose **Sending access**, and restrict it to **mail.kousa.app**. Save the key directly in the ignored environment file below. Resend shows the key only once.

Cloudflare is already the authoritative DNS provider, so no further Namecheap nameserver change is needed. Resend supports sending from any address at a verified domain; a separate mailbox is not needed for the sender. This setup does not create an inbox for replies.

Official guides: [add and verify a domain](https://resend.com/docs/add-a-domain), [create a scoped API key](https://resend.com/docs/create-an-api-key), and [verified-domain features](https://resend.com/docs/dashboard/domains/introduction).

## Environment and Alchemy

Set these in `apps/web/.env`, then restart `pnpm run dev` from the repository root:

```dotenv
EMAIL_FROM=invites@mail.kousa.app
RESEND_API_KEY=your_resend_sending_key
```

Keep the API key out of chat and version control. Alchemy reads the local environment file and supplies `RESEND_API_KEY` as a secret to local development and the deployed Worker. `EMAIL_FROM` defaults to the sender above. The installed Alchemy version has no Resend domain resource, so domain verification and DNS setup are managed in the dashboards.

Both Node development and the deployed Cloudflare Worker use the same [Resend Send Email API](https://resend.com/docs/api-reference/emails/send-email). Without a valid sender and a nonempty key, invitations are saved with **Not sent**. Configuration alone cannot confirm that the key is authorized or the domain verified; that requires a real send.

Invitation and verification links use `BETTER_AUTH_URL`. A `localhost` link only works on the machine running Kousa. Set up a public application deployment before inviting people on other machines. Verifying the email-sending domain does not deploy the website. Alchemy supplies the Worker URL in production; revisit the URL and trusted origins when attaching the public `kousa.app` website domain.

## Delivery behavior

The transport aborts requests after 20 seconds, saves safe delivery error codes, and does not retry automatically after an uncertain result. A hash of the full message is sent as a [Resend idempotency key](https://resend.com/docs/dashboard/emails/idempotency-keys), which deduplicates identical submissions for 24 hours without exposing the recipient or invitation token in the key. An owner-triggered resend creates a fresh invitation link and therefore a new key.

**Sent** means Resend accepted the message and returned a message ID. Inbox delivery, opens, and delayed bounces are not tracked. Check Resend's email dashboard when investigating delivery problems.

## Verify setup

1. Send an invitation to an address you control from an owned project. Confirm **Sent**, the chosen role, and the expiry.
2. Open the email link and sign in with that address. Verify the address if prompted, return to the invitation, and accept. The owner should see **Accepted**, and the recipient should see the correct project role.
3. An unrelated account must not be able to view or accept the invitation. Resending must invalidate the previous link. Revocation must block acceptance.

`pnpm test` covers the Resend transport and invitation rules without sending real messages. A real delivery check requires the verified domain, API key, and a test recipient.
